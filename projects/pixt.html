01PROJECT OVERVIEW

하나의 플랫폼, 서로 다른 역할

공통 UI는 재사용하고, 서비스별 비즈니스 로직은 각 프로젝트의 맥락에 맞게 구성했습니다.

“복잡한 서비스일수록
공통 요소와 고유한 역할을
명확히 구분해야 한다.”

Pixt는 영상 콘텐츠를 찾고 구매하는 사용자와 콘텐츠를 공급·관리하는 사용자가 만나는 플랫폼입니다. 프로젝트가 확장되면서 기존 Web 코드베이스에서 공통 UI를 분리하고, Web과 Auth 서비스를 별도 Workspace로 구성한 변경을 살펴볼 수 있습니다.

06ENGINEERING / SEARCH

많은 영상도 가볍게 탐색하도록

CHALLENGE

목록이 길어질수록 부담이 커지는 검색 화면

영상 콘텐츠 검색은 썸네일 카드가 누적되는 인터페이스입니다. 화면 크기에 따라 배치가 달라지고, 사용자는 스크롤하면서 계속 새로운 콘텐츠를 탐색합니다.

APPROACH

렌더링 범위와 데이터 요청 시점을 분리

AutoSizer로 가용 너비를 측정하고, VariableSizeGrid로 셀을 구성합니다. 렌더링된 행 범위를 이용해 다음 커서 데이터를 요청합니다.

  1. 01

    Search API

    검색어·필터와 커서를 전달하고 콘텐츠 목록 요청

  2. 02

    Responsive Grid

    AutoSizer의 너비를 기준으로 1~4열 구성

  3. 03

    Virtual Rendering

    VariableSizeGrid로 화면에 필요한 셀 중심 렌더링

  4. 04

    Load Next Page

    overscanRowStopIndex로 하단 접근을 감지해 다음 커서 요청

InfiniteList / implementation excerpt
const columnCount = width >= 1680 ? 4
  : width >= 1024 ? 3
  : width >= 429 ? 2 : 1;

const rowCount = Math.ceil(list.length / columnCount);

<Grid
  columnCount={columnCount}
  rowCount={rowCount}
  onItemsRendered={({ overscanRowStopIndex }) =>
    onRenderNext?.(overscanRowStopIndex, rowCount)
  }
/>

실제 핵심 처리 흐름을 읽기 쉽게 축약한 예시입니다.

IMPLEMENTATION POINTS

화면과 데이터의 경계를 명확하게

  • 뷰포트에 맞춰 1~4열을 선택
  • 셀 크기를 기준으로 행 개수 계산
  • 스크롤된 범위를 확인해 추가 요청 조건 판단
  • 검색 결과의 next 커서를 이용해 목록 확장

실제 렌더링 시간이나 메모리 사용량의 개선 수치는 측정 자료가 없어 기재하지 않았습니다.

STATE MANAGEMENT

로그인 전후 장바구니

비로그인 장바구니는 브라우저에 저장하고, 로그인 후 rebaseUserCartList()로 서버에 반영한 다음 최신 목록을 조회합니다. 성공하면 기존 로컬 저장값을 제거합니다.

SERVICE INTEGRATION

Web과 Auth 사이의 Bridge

Web의 Bridge는 전달된 인증 정보를 반영하고 setUser(), setCartList()를 실행한 뒤 목적지로 이동합니다. Auth에도 Bridge 페이지가 있어 경로를 처리합니다.

구현 범위 안내

결제·구독 관련 화면과 API 연동은 확인되지만, 일부 카드 등록 모달 및 성공 페이지 연결은 제공된 소스에서 완성 여부를 확인할 수 없습니다. 백엔드 인증·결제 처리나 Docker 설정을 개인 구현 성과로 주장하지 않습니다.

09ENGINEERING REVIEW

확장할수록 중요해지는 경계와 안정성

소스를 다시 검토하면서 확인한 개선 과제를 현재 구현과 구분하여 정리했습니다.

01 / PACKAGE BOUNDARY

공통 코드의 버전 동기화

Web과 Auth Workspace에 Design System 소스가 각각 존재합니다. 현재 공유하는 UI 구현은 대부분 같지만, 장기적으로는 변경 사항의 동기화와 패키지 버전 전략이 중요합니다.

02 / SEARCH STATE

연속 페이지 요청 제어

검색 목록의 끝을 감지해 다음 페이지를 불러올 때, 로딩 중복 요청 방지와 더 이상 조회할 데이터가 없는 상황을 명시적으로 처리하면 안정성을 높일 수 있습니다.

03 / CROSS-SERVICE AUTH

서비스 간 인증 전달 보강

Bridge에서 URL 파라미터를 파싱하고 인증 상태를 갱신합니다. 토큰 노출 가능성과 잘못된 경로·파라미터에 대한 예외 처리는 추가 검토가 필요한 부분입니다.

PROJECT TAKEAWAY

일관된 UI는 함께 사용하고,
서로 다른 서비스의 문제는 각자의 구조 안에서 해결했습니다.

Pixt에서 확인되는 핵심은 단순히 페이지를 구현하는 것을 넘어, 공통 컴포넌트와 서비스 전용 기능을 구분하고 검색·인증·장바구니 같은 실제 사용 흐름을 연결한 경험입니다.
